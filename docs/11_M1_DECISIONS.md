# M1 工程决策与接口边界

用户已初步验收 M0，并明确授权 M1。此次仅实现“真实文字记录 → 候选长期记忆 → 有来源检索”，完成后等待用户验收，不进入 M2。

## 延续 M0

- 开发分支 `feat/m1-text-memory`，起点 `61395e1`。保留 Expo SDK 57、React Native、TypeScript、FastAPI、SQLAlchemy、Alembic 和 SQLite WAL。
- M0 演示页面和回归测试保留；新增文字工作区处理真实持久化操作。Mock 是抽取算法的模式，不表示在文字工作区里保存的内容是预置假记录。
- 不引入录音、转写、通知、后台 Worker、向量库、自动冲突分类或云部署。

## 数据与可靠性

- 每次沟通是独立记录，UTC 时间保存；新增一条 150 万元信息不会覆盖或删除以前的 200 万元记录。
- 手动关联采用 `people/projects/events: string[]`，由服务端归一化关联到同一用户的人物、项目和事件。这里的事件关联是人工标签，不声称自动推断真实人物身份。
- 原始记录保存与候选抽取分开。保存后由用户请求抽取，模型失败时已保存记录仍可读取，允许重试。
- 记录与记忆采用 `version/expected_version` 乐观并发控制；编辑留历史，旧来源版本的候选失效或标记被替代，不能悄悄引用已改变的正文。
- 删除由用户明确确认，清理该记录的正文、历史和依赖记忆；保留不含原文的幂等墓碑，防止旧请求重放造成记录复活。不是“删除一条最新报价就清空历史其他记录”。
- 离线草稿和已授权发送队列在客户端持久化，队列保存不可变请求和稳定 Idempotency-Key。响应丢失时重发同一键，服务端返回同一资源；同键不同内容返回冲突。没有写盘成功就不能显示“已保存草稿”。

## 证据与可信度

- 候选始终包含来源 ID、来源版本、原文字符范围和精确摘录、记录时间、可空的事件时间、类型及确认状态。
- 候选、推测、人工已确认、驳回、被替代分别标识。更正不会自动成为已核实事实；推测被确认后仍保留推测类型。
- 默认 Mock 采用确定性文字抽取，可处理输入的虚构文字，不能用三条预写答案冒充真实模型。
- M1 问答采用保守的关键词 / 实体检索，按时间列出有权限且有效的原话，并说明局限。不做未经证实的审批、意图或违约结论；问题没有相关证据时明确拒答。
- 200 万、尚未批准、150 万三次输入作为独立验收场景，检查原文保留、同一人物项目关联、精确引用，以及没有虚构“200 万曾获批准”。

## 安全与隐私

- 业务 API 均使用配对设备令牌，服务端仅存令牌哈希。短期一次性配对码由本机命令生成并写入 Git 忽略文件；不能在聊天或日志中输出。
- 原生设备令牌存 SecureStore；Web 仅使用当前浏览器会话存储，不能称作 iOS 同等安全。草稿持久存储未加密，只用合成资料验收。
- 模型密钥仅留在服务端本地配置。默认不联网；Live 抽取须服务端显式配置，并由用户在每次发送前确认。ASR 仍独立且未启用。
- 日志和审计只记录 ID、操作、状态、请求 ID、提供方及可确认的计量，不记录原文、密钥和配对码。价格未知时不伪造费用为零。
- SQLite、客户端草稿、WAL 和备份尚未达到生产级静态加密，不得用真实私人谈话或商业机密测试。

原规范未改写；本文件记录 M1 的最小实现选择。实际端点、测试结果、限制和 Git 提交见 `M1_ACCEPTANCE.md` 与 `PROGRESS.md`。

## 配置和实现补充

- 根`.env.example`只供服务端。Live须同时设置`MOCK_MODE=false`、`LIVE_AI_ENABLED=true`、`LLM_PROVIDER=openai_compatible`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`及逗号分隔的精确`LLM_ALLOWED_HOSTS`。Base URL是带API前缀的HTTPS地址，Adapter追加`/chat/completions`；只支持443、公网DNS、无URL凭据和query，拒绝跳转与私有地址并固定已校验IP连接。部署者仍需自行验证供应商的JSON Schema兼容性。
- 客户端只读取安全的目标host，逐次同意后传`allow_live_ai=true`；不接受客户端传来的供应商密钥、目标URL或主机白名单。Meta不返回密钥或完整模型URL。
- 调用前后不持有跨网络的SQLite写锁；响应返回后重新核对来源版本。若来源变更，拒绝旧候选，用量尝试仍落库；计量和价格未取得时保持null。
- `recorded_at`是原文创建保存时间，`captured_at`是用户填写的沟通时间，`event_time`没有逐字证据时为空。UTC固定六位小数，防止字符串排序混淆同秒先后。
- 证据坐标统一为Unicode码点，客户端使用`Array.from`切片。正文不做strip或Unicode重写；标题和关联名可以归一化，原始文字前后空白原样保存。
- M1迁移是冻结的DDL，不从未来版本ORM元数据动态生成；本次验证了升级、降级及再次升级。
- 检索只生成固定模板及逐字引用，未调用生成模型回答。人工关联的同项目/事件原文可作为上下文一并展示，但不自动判定变化或矛盾。审批、签约等结论仅有预计或计划时不作成立判断。
- 本机浏览器预览已恢复到8000/8081，未将测试故事写入日常库。M1自动化使用临时SQLite并在退出后清理，所有测试均为虚构数据。
