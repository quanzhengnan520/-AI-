# 04｜Codex 分阶段开发清单与验收门槛

执行规则：**一次只做一个里程碑**，每一阶段都必须产生能运行、能验收、能回退的成果。M0 完成即停止，等待用户决定是否开始 M1。所有时间/价格是待实测项目，本文不许编造工期保证。

## M0：工程骨架 + 真能运行的手机 UI + Mock 后端（第一条指令执行）
任务：
- 检查 Windows Node/npm、Python、Git、Expo/EAS 工具可用性；有冲突先说明。
- 初始化仓库与目录、README、`.gitignore`、`.env.example`、依赖锁文件；根目录启动手册。
- Expo Router：四个主区域“今天/记录/记忆/我的”，从“今天”进入“问一问”；页面包含录音浮层、记录详情、记忆详情、提醒列表与设置。可以所有数据标“演示数据”。
- FastAPI `/health` 与 `/api/v1/meta`；测试基准、统一错误对象；Mock provider 结构。
- 默认不需要 API Key、不连接外部云服务；App 可以使用固定 mock adapter 模拟页面，有明确切换网络 API 配置，但生产不能使用 hardcoded auth。
- 完成后端 pytest / 移动端 typecheck / lint / 可用的本地启动烟测。

验收：界面可在 Expo 开发环境展示，导航无崩溃；可见 Mock 标签；README 的 Windows 步骤正确；没有真实用户音频上传；`docs/PROGRESS.md` 中明确真机是否已测。**M0 不要求后台录音，不要求付费 Apple 账户。**

## M1：真实文字记录 → 候选记忆 → 有来源检索（首个价值闭环）
任务：
- SQLite 模型与 Alembic；设备配对/token；结构错误与日志去敏。
- 创建/编辑/删除文字记录，时间线与检索，支持人物/项目手动标签。
- Mock 记忆抽取必须可用于回归测试；若用户配置了真实 API，才走 LLM Adapter；JSON Schema 校验与原文锚点验证。
- 候选记忆列表、来源定位、用户确认/驳回；断网草稿保存在设备，回连可重试同步。
- 中文关键字检索和未命中提示；最小费用日志与请求 ID。

验收：合成记录输入后，能点进依据并定位引用；“没有证据”的问题拒绝猜测；关闭/重启进程数据保留；重发相同 Idempotency-Key 无重复记录；未鉴权请求拒绝。

## M2：真实录音与异步转写
任务：
- `expo-audio` 麦克风权限、录音 UI、暂停/恢复/停止、持久 document 目录存储与录音时长。
- 文件名采用随机标识，不直接含人物真实姓名；上传队列、断网重试、上传进度、取消、大小与类型限制。
- 后端音频存储与上传元数据；`jobs`+Worker；可插拔 ASR（Mock 必须可运行、Live 需要实际配置）；转写片段映射时间锚点。
- 验证有用户明确启用的后台录音：Expo config plugin 的背景录音配置；在专门的开发版/真机版测试锁屏继续录音、电话打断、耳机插拔、强制关闭等边界。

验收：用户授权后的 1–5 分钟真实录音能被保存、可回放、上传、显示转写/失败状态；断网后本地不丢数据；后台录音“未测/通过/失败”逐项标记；没有苹果签名条件也可以先验收前台录音，不得虚假通过锁屏项。

## M3：跨时间可信记忆与证据问答（核心差异化）
任务：
- 事实 `event_time/recorded_at/valid_from/to` 正确；人物和项目实体；版本历史与用户纠错。
- 跨记录关联、预算变化/承诺变化/审批状态变化、冲突候选；区分“同一时点互相矛盾”和“不同时间正常变化”。
- 文本检索与候选证据重排；可选向量检索实验；证据验证后才给模型生成回答。
- QA 展示引用、证据截图/文字定位、不确定性；对恶意提示注入和资料内伪指令有防护。
- 用 fixtures 至少 30 条合成谈话扩增为有标签回归集；记录样本数和准确性，不夸大泛化。

验收：预算故事能正确解释历史变化且不说“预算已经批准”；没依据不能编造；记忆修改能查旧版本；每个引用正确定位合法来源；成本数据可查看。

## M4：提醒、保留清理、导出删除、可用性完善
任务：
- AI 只**提议**提醒，用户审核后创建任务；用户控制提醒时间、静默时段、敏感内容锁屏隐藏。
- `expo-notifications` 本地计划通知；在 App 被关闭/权限被拒绝的条件下说明实际效果，不承诺无限后台 AI 推理。
- 默认 30 天原始资料清理前提醒与延长/立即删除；已删除来源的证据状态处理与证据摘录选择。
- 支持导出 JSON/Markdown（如用户选择含音频则以受保护下载打包）；删除某条、删除某人、删除全部的模拟预览与最终执行。
- 数据备份/恢复的最低操作手册、每日成本阈值/限额。

验收：拒绝通知权限时 App 不崩溃；提醒不在未确认时自动对外行动；清理后原音频不可播放；用户能导出并核对内容，删除后检索无残留。

## M5：iPhone 真机闭环与 30 天自用试验
任务：
- 如用户已具备签名条件，配置 EAS iOS dev/preview build、设备注册、安装，检查实际麦克风/文件访问/本地通知/锁屏录音等。
- 记录所有系统限制：锁屏、来电、低电量模式、断网、后台被系统杀死、弱网、录音时耗电/温升、同步时间。
- 设置能采集**非敏感匿名质量指标**的用户反馈流程：回答是否有帮助、引用是否正确、误报/漏报、每天使用次数、模型成本。
- 使用合成材料完成正式安全测试后，再由用户自行选择少量已获许可的真实记录试运行；不自动导入手机联系人/微信/通话。
- 给出是否进入“独立 4G 硬件 POC-01” 的 Go/No-Go 评审材料。硬件可行性尚待工程单独验证。

验收：真实 iPhone 安装成功的证据、具体功能实测清单、已知系统边界与质量/成本报告；若未安装，诚实给出阻碍，不把 M5 标成完成。

## 每阶段统一交付格式（Codex 按此回复）
1. 本次完成的需求编号/功能点。
2. 修改文件清单及理由。
3. 本地如何运行：Windows PowerShell 逐条命令。
4. 自动测试命令、通过数、失败数、跳过原因。
5. 手工验收步骤与模拟/实测标记。
6. 风险、已知缺陷、下一阶段依赖。
7. 更新 `docs/PROGRESS.md`，附本次 Git commit ID（若可提交）。

## 停止条件
- 真机签名需要账号/费用；没有则暂停真机步骤，不阻塞 Mock/后端。
- 无模型 API：必须切换 Mock，不能要求必须先付费才能跑通基础 UI。
- 用户录音权利不清楚：停止真实录音数据采集，继续使用虚构测试资料。
- 任何删除或公网部署动作：必须由用户明确触发。
