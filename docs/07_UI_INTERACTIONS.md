# 07｜iPhone App 页面、状态与中文文案

## A. 视觉与操作原则
- 为真实移动场景设计：大录音按钮、单手可达、字体清晰、长内容能听/读、每一条分析随时可看来源。
- 采用 iOS 熟悉的导航和交互；不用复杂桌面控制台、不做夸张“AI 灵魂”数字人；内容可信度优先于动画。
- 主导航建议四 Tab：**今天、记录、记忆、我的**；“问一问”作为首页突出入口。任务/提醒可从“今天”访问。
- 色彩简洁；明确区分真实、模拟、推测、待确认、错误，不用过度装饰。

## B. 页面信息架构
**Onboarding 初次进入**：产品做什么/不会做什么 → 本地与云端资料处理说明 → 选择 Mock 演示/真实服务 → 麦克风权限按需申请 → 设置默认原始资料保留 30 天 → 设备安全配对（真实模式）。不强制先开通知。

**首页“今天”**：当前日期、问一问输入框/按住说话入口、醒目的“开始记录”、今日待办、近期值得核实的变化卡片（必要时 Mock 标签）、近期记录入口、同步状态、费用异常提醒。

**“开始记录”底部弹层**：录制时长、实时录音中标志、暂停/继续、完成；录音前展示简短 consent 提示；停止后选择标题/标签/是否上传处理。没有权限时给“去设置”和“用文字记录”。

**记录列表**：按时间；状态标签（仅本机/待同步/转写中/待确认/完成/失败）；搜索；进入详情。

**记录详情**：标题、记录时间、录音/播放（如有且仍保存）、转写分段、用户修订按钮、候选事实/任务、关联人物、原始资料保留期限与删除按钮；从记忆引用跳转并高亮相应片段。

**记忆首页**：人物/项目筛选、关键事实、待核实/用户确认、按时间线查看变化；避免一次铺满上百条摘要。

**记忆详情**：一条事实 + 原始证据位置 + 来源状态 + 陈述/推断区别 + 纠错/确认/驳回 + 历史版本 + 相关信息。关键的“有效时间”和“记录时间”有分别说明。

**问一问**：语音/文本问法、答案、引用来源卡、明确的“依据不足”、选择是否保存为待办、纠错按钮。AI 生成中可取消。

**待办/提醒**：候选待办（需用户确认）与已确认待办，支持日期/重复/静默时段/完成/取消；不默认自动外发。

**“我的/设置”**：Mock/Live 模式、模型提供方（只显示标识而非密钥）、权限状态、连接状态、费用统计、时区、通知隐私、资料保留政策、原话摘录许可、导出/删除、说明与反馈。

## C. 关键中文文案（可按 iOS 实际 UX 调整）
- 初次使用：“它会帮你记住重要信息，并展示判断依据。AI 的推测不等于事实。”
- 录音许可：“请先确认本次对话的录音已获得所需同意，并符合适用规则。”
- 录音中：“正在录音 · 00:02:18”，一直可看见停止键。
- 保存成功：“录音已安全保存到本机，尚未同步。”（只有本机实际写盘后显示）
- 转写中：“录音已上传，正在识别语音；你可以稍后查看结果。”
- 引用不足：“我没有找到足以确认这件事的记录。可以补充相关资料。”
- 变化发现：“我发现两次说法发生变化，但暂时不能判断原因。”
- 低可信：“这是一项推测，建议核实后再作为依据。”
- 证据已删除：“原始录音已按保留规则删除，此处仅显示经你授权保留的摘录/摘要。”
- 模型失败：“这次 AI 分析没有成功。你的原始记录仍然保存，可以重新尝试。”
- 通知拒绝：“系统通知未开启。你仍可在 App 内查看提醒。”
- 演示数据：“演示内容 · 不代表真实识别或分析结果”。

## D. 状态/错误清单
- 麦克风拒绝、录音途中来电、磁盘不足、录音失败、后台恢复、网络断开、弱网、文件超限、ASR 服务无权限、模型 API 余额不足、模型 JSON 不合格、无证据、上传重复、后台任务失败、权限撤销、令牌失效、时区改变、提醒权限拒绝、证据过期、正在删除。
- 每个状态要有用户可理解的恢复路径：重试/稍后再看/仅本地保存/打开设置/取消/联系客服（后期），而不是“Unknown error”。
