# 06｜隐私、安全、数据所有权与权限设计

> 这是工程安全基线，不构成律师对中国或其他司法辖区录音、个人信息保护法律的最终意见。真实商业部署前需要按目标地区复核。

## 1. 原则
- 默认最小化采集：用户主动输入/启动录音，不自动抓取联系人、微信、手机通话、相册、地理位置。
- 明确区分资料类别：原始音频、转写全文、长期记忆事实、可选保留的原话摘录、待办、调用日志。
- 录音前明确提示用户需获得相关参与者同意并遵守适用法律；App 内清晰显示“正在录音”，提供随时停止；不能设计隐蔽录音功能。
- 将个人资料传至第三方模型/API 前，明确告知提供商、用途、所传数据类型和可否关闭；用户主动启用 Live 后才发送。
- 默认以合成数据开发；真实商务会谈需额外注意保密协议、个人信息、商业机密、数据出境限制；没有许可不上传到不受控的 AI 提供商。

## 2. 密钥与鉴权
- 后端持有供应商 `LLM_API_KEY`、`ASR_API_KEY`，绝不置入移动端 JavaScript、Expo public env、日志或源码。
- 移动端的**设备访问令牌**由安全配对后生成，仅存 SecureStore；后端只存令牌哈希；支持撤销/轮换。
- 首次开发配对可用服务端一次性码，不能把写死在 Git 的 `DEV_TOKEN` 当生产认证。
- 上传/检索/删除/导出接口全部鉴权、校验资源归属；开发模式 HTTP 只可限可信 LAN，不开放公网。
- 服务端所有外部 provider URL 使用白名单/配置项，避免任意 URL 透传造成 SSRF；日志过滤 URL 查询中的 Token。

## 3. 数据安全边界
- HTTPS 传输；正式公网接口不得绕过 TLS 验证。
- SecureStore 适合少量秘密，**不是**长期音频或大文本数据库。
- iPhone 录音存 app document（非易清理 cache）并遵守系统数据保护配置；服务端 SQLite **默认不自带静态加密**。POC 若运行本地请使用可信设备、系统全盘加密与受控目录；不能对外宣称“端到端加密”。
- 真实云部署前需要明确静态加密、备份加密、日志保留、服务端管理员权限、事故处理与密钥轮换。
- 仅记录最小可调试日志：ID、时长、状态码、错误码和消耗；默认不打印录音正文、完整模型上下文、密钥、原话片段。

## 4. 数据保留与证据矛盾的处置
- 原始音频和全文转写默认 30 天到期（可调整）；提前提醒，展示清理倒计时。
- “事实性智能记忆”不同于原始材料；继续保留的依据必须透明。长期保留原话摘录需要单独告知/授权、可随时撤销。
- 原始文件过期后，标为 `original_deleted`；如果没有单独摘录同意，就不要继续声称可回放或精确引用。
- 删除某条记录时预先列出关联事实、待办、缓存、索引的处理政策：默认**连带删除依赖内容**，除非用户明确选择保留某条已经独立确认的记忆。
- 全量删除要尽可能物理清除主库和文件、撤销会话、停止队列，并说明备份延迟。不能仅设置 UI 上“删除成功”而后台继续可查。

## 5. AI 输出安全
- “分析/推断”不得变成“事实”；特别是对他人意图、商业谈判、法律风险的推断，必须写明依据和替代解释。
- 抽取模型输出是候选事实；存在 schema 校验、来源锚点、人工修正流程。
- 外部资料中的“忽略系统提示词”是被处理的数据，不得改变 AI 系统指令或触发未经授权的操作。
- 发送消息、删数据、访问外部系统、付款、共享记录等操作必须单独明确授权；首版根本不实现自主对外操作。

## 6. iOS 系统权限与合规
- 麦克风权限说明应简洁准确；用户拒绝时文字功能可继续。
- `expo-audio` 的后台录音支持是有前提的系统能力，不能暗示 iOS 保证全天候无限运行；App 被强制关闭/系统中断必须停止或恢复状态。
- 通知权限非强制；默认锁屏通知文案使用“你有一条待确认事项”，避免透露姓名/报价。
- Apple App Review Guideline 2.5.14 要求对录音/记录用户活动有明确同意与可见/可听指示；2.5.4 限定后台服务正当用途；5.1 涉及数据收集/删除/共享；开发和上架前应复核现行原文。

## 7. 隐私测试清单
- 检查源代码、构建产物、崩溃日志是否包含 API Key、可识别用户资料。
- 未授权不能获取源文件、导出、删除他人数据；Mock 与 Live 数据存储位置明确分隔。
- 切换 Live Provider 前弹窗显示数据将送至哪个模型提供商，允许取消。
- 导出/删除有确认页面与进度/失败报告；不能部分失败却展示全部成功。
